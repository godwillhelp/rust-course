Cargo, переменные и числа

Ставим на место инструменты, учимся читать компилятор как собеседника и разбираем, как Rust хранит числа и что он делает, когда число не влезает в свой тип.

Rust 1.100.0edition 2024≈ 3–4 часаКнига: гл. 1, 3.1, 3.2

После лекции вы сможете

  • объяснить, что делают rustup, rustc, cargo, clippy и rustfmt;
  • создать, проверить, запустить и протестировать проект через cargo;
  • разобрать сообщение компилятора по частям и найти объяснение по коду ошибки;
  • выбирать между let, let mut, const и затенением;
  • выбрать подходящий целочисленный тип и предсказать результат приведения as;
  • сказать, что произойдёт при переполнении в debug и в release, и обработать его явно.

Как работать с лекцией: весь код набирайте руками в своём проекте, а перед каждым запуском записывайте предсказание. Ошибка в предсказании полезнее правильного ответа: именно она показывает, где модель в голове расходится с языком.

Каналы и релизы

У Rust три канала. stable выходит раз в шесть недель, сейчас это 1.100.0. beta станет следующим stable. nightly собирается каждую ночь и содержит нестабильные возможности. В курсе мы используем только stable. Обновление: rustup update, текущее состояние: rustup show.

Редакции

Редакция (edition) и версия компилятора — разные вещи. Версия меняется каждые шесть недель. Редакция меняется раз в несколько лет (2015, 2018, 2021, 2024) и позволяет вводить несовместимые изменения синтаксиса, не ломая старый код: компилятор 1.100 собирает пакеты любой редакции, и пакеты разных редакций свободно используют друг друга. Редакция пакета записана в его Cargo.toml. Мы пишем на 2024.

Профили dev и release

Обычная сборка использует профиль dev, сборка с --release — профиль release. Это не просто «с оптимизацией и без»: профили меняют поведение программы. Ниже выдержка из настроек по умолчанию (Cargo Book, «Profiles»):

Cargo.lock и target/

Cargo.lock фиксирует точные версии всех зависимостей. Его создаёт cargo, руками не правят, в git коммитят. Папка target/ — результат сборки, она большая и всегда в .gitignore.

В нашем репозитории

Репозиторий курса — это workspace: один Cargo.toml в корне объединяет все задания всех лекций. Команды запускаются из корня, а пакет выбирается флагом -p: cargo test -p l01-task1, cargo run -p l01-task2.

§3Как читать ошибки компилятора

В Rust компилятор останавливает много ошибок, которые в других языках всплывают только при запуске. Поэтому вы будете много читать его сообщения. Они написаны для людей и почти всегда подсказывают исправление. Разберём одно сообщение по частям.

src/main.rsошибка компиляции
fn main() {
    let hp = 100;
    println!("HP: {hp}");
    hp = 90;
    println!("HP: {hp}");
}
1error[E0384]: cannot assign twice to immutable variable `hp`
2 --> src/main.rs:4:5
  |
2 |     let hp = 100;
  |         -- first assignment to `hp`   3
3 |     println!("HP: {hp}");
4 |     hp = 90;
  |     ^^^^^^^ cannot assign twice to immutable variable   4
  |
5help: consider making this binding mutable
  |
2 |     let mut hp = 100;
  |         +++
  1. Уровень и код. error останавливает сборку, warning — нет. Код E0384 можно расшифровать командой rustc --explain E0384 или в индексе ошибок.
  2. Место: файл, строка 4, столбец 5. В Zed по нему можно кликнуть.
  3. Вторичная метка (---, синим) показывает связанное место: где переменная получила первое значение.
  4. Основная метка (^^^, красным) показывает само нарушение.
  5. help предлагает исправление в виде патча: +++ под строкой показывает, что добавить.

Порядок чтения

  1. Исправляйте первую ошибку. Остальные часто являются её следствием и исчезнут сами.
  2. Читайте сообщение целиком, включая метки и note. Ответ обычно уже там.
  3. Не применяйте help вслепую: это догадка компилятора о вашем намерении. Сначала поймите, почему он так предложил.
  4. Если есть код E…, прочитайте rustc --explain: там пример ошибки и её исправления.

Ошибки без кода: линты

Некоторые ошибки приходят без кода E…. Это линты, проверки с настраиваемым уровнем: allow (молчать), warn, deny (ошибка), forbid (ошибка, которую нельзя понизить). Часть линтов уже стоит на deny, и строка note это сообщает:

error: literal out of range for `u8`
 --> src/main.rs:2:21
  |
2 |     let level: u8 = 256;
  |                     ^^^
  |
  = note: the literal `256` does not fit into the type `u8` whose range is `0..=255`
  = note: `#[deny(overflowing_literals)]` on by default

Предупреждения тоже стоит читать. Неиспользуемая переменная почти всегда означает опечатку или забытый код. Если переменная не нужна намеренно, начните её имя с подчёркивания: _x.

Бестиарий

В корне репозитория лежит bestiary.md. Каждая новая для вас ошибка компилятора, которую вы записали и объяснили своими словами, приносит +5 XP.

§4Переменные

Переменная объявляется через let и по умолчанию неизменяема. Так проще читать код: если нет mut, значение не меняется, и это не надо проверять глазами. В многопоточном коде (лекция 25) это свойство становится ещё важнее.

src/main.rsЗолото: 0, HP: 100 / HP после удара: 90
fn main() {
    let gold: u32 = 0;
    let mut hp = 100;
    println!("Золото: {gold}, HP: {hp}");
    hp = 90;
    println!("HP после удара: {hp}");
}

let gold: u32 — явная аннотация типа. В строке let mut hp = 100 тип выведен компилятором. Вывод типов работает по всей функции, но если подсказок нет, целое число получает тип i32.

Переменную можно объявить без значения, но читать её до присваивания нельзя. Rust проверяет это при компиляции, а не надеется на значение по умолчанию:

error[E0381]: used binding `gold` isn't initialized

Константы

const MAX_HP: u32 = 100;
const SECONDS_IN_DAY: u32 = 24 * 60 * 60;

fn main() {
    println!("{MAX_HP} {SECONDS_IN_DAY}");
}
  • тип указывается всегда, вывода нет (const MAX_HP = 100; — ошибка «missing type for `const` item»);
  • значение вычисляется при компиляции, поэтому в нём допустимы только константные выражения;
  • имя пишется SCREAMING_SNAKE_CASE;
  • константу можно объявить в любой области, в том числе вне функций.

Затенение

Повторный let с тем же именем создаёт новую переменную, которая закрывает старую до конца блока.

src/main.rsВнутри блока x = 12 / Снаружи x = 6
fn main() {
    let x = 5;
    let x = x + 1;
    {
        let x = x * 2;
        println!("Внутри блока x = {x}");
    }
    println!("Снаружи x = {x}");
}

Чем затенение отличается от mut:

  • новая переменная может иметь другой тип: let spaces = " "; let spaces = spaces.len(); компилируется, а с let mut то же самое даёт E0308 (несовпадение типов);
  • после затенения переменная снова неизменяема, если её не объявили через mut;
  • затенение во внутреннем блоке заканчивается вместе с блоком.
Если вы пришли из C#

В C# локальная переменная изменяема по умолчанию, а повторное объявление имени в той же области запрещено. В Rust наоборот: изменяемость надо запросить, а повторное объявление разрешено. const похож на C#-овский const, но тип в Rust обязателен.

Имена переменных и функций пишутся snake_case. Это не только соглашение: на myVar компилятор выдаст предупреждение non_snake_case.

§5Скалярные типы

Скалярный тип хранит одно значение. В Rust их четыре вида: целые числа, числа с плавающей точкой, bool и char.

Целые числа

Знаковый тип с n битами хранит значения от −2n−1 до 2n−1−1, беззнаковый от 0 до 2n−1. Точные границы есть в константах: u8::MAX, i32::MIN. usize используется для индексов и размеров: длина массива имеет тип usize.

Какой тип выбирать: если нет причины для другого, берите i32. Для индексов и длин — usize. Если значение по смыслу не бывает отрицательным и у него известный предел (здоровье, уровень, количество в стаке), подойдёт беззнаковый тип нужного размера.

Литералы

src/main.rs1000000 255 493 240 65 57 2.5 0.1
fn main() {
    let million = 1_000_000;
    let mask = 0xff;
    let perms = 0o755;
    let flags = 0b1111_0000;
    let letter = b'A';
    let small = 57u8;
    let ratio = 2.5;
    let precise: f32 = 0.1;
    println!("{million} {mask} {perms} {flags} {letter} {small} {ratio} {precise}");
}
  • _ разделяет разряды и ни на что не влияет;
  • 0x, 0o, 0b — шестнадцатеричная, восьмеричная и двоичная запись;
  • b'A' — байт-литерал, тип u8, только для ASCII;
  • суффикс задаёт тип: 57u8, 1_000i64, 2.5f32;
  • без подсказок целый литерал получает i32, дробный — f64.

Числа с плавающей точкой

f32 и f64 — числа стандарта IEEE 754 одинарной и двойной точности. По умолчанию берите f64: на современных процессорах он почти не медленнее, а точнее. Дроби вроде 0,1 в двоичной системе не представимы точно, поэтому:

src/main.rs0.30000000000000004 / false / true inf
fn main() {
    let sum = 0.1 + 0.2;
    println!("{sum}");
    println!("{}", sum == 0.3);
    let nan = 0.0_f64 / 0.0;
    println!("{} {}", nan.is_nan(), 1.0 / 0.0);
}

Деление дробного на ноль не вызывает панику: результат — бесконечность (inf) или NaN («не число»). NaN не равен ничему, даже самому себе, поэтому проверяют его методом is_nan(). Запись x == f64::NAN всегда ложна, и компилятор предупредит об этом линтом invalid_nan_comparisons.

bool и char

bool занимает 1 байт и принимает значения true и false. char занимает 4 байта и хранит одно скалярное значение Юникода: любой символ от латиницы до эмодзи. Пишется в одинарных кавычках, строки — в двойных.

src/main.rs122 1103 129408 / 4
fn main() {
    let latin = 'z';
    let cyrillic = 'я';
    let crab = '🦀';
    println!("{} {} {}", latin as u32, cyrillic as u32, crab as u32);
    println!("{}", size_of::<char>());
}
Если вы пришли из C#

В C# char — это 2 байта, одна кодовая единица UTF-16, и 🦀 в него не помещается. В Rust char всегда вмещает целый символ. Строки при этом хранятся в UTF-8, а не как массив char; это тема лекции 5.

Арифметика

Операции + - * / % работают только с одинаковыми типами. Неявных преобразований чисел в Rust нет вообще, даже расширяющих:

let a: i32 = 5;
let b: i64 = 10;
let c = a + b;
error[E0308]: mismatched types
  ^ expected `i32`, found `i64`

То же касается смеси целых и дробных: 2.0 * 3 не скомпилируется (E0277, «cannot multiply `{float}` by `{integer}`»). Пишите 2.0 * 3.0.

src/main.rs3 -3 / 1 -1 / 3.5
fn main() {
    println!("{} {}", 7 / 2, -7 / 2);
    println!("{} {}", 7 % 2, -7 % 2);
    println!("{}", 7.0 / 2.0);
}

Целочисленное деление отбрасывает дробную часть, то есть округляет к нулю: −7 / 2 = −3, а не −4. Остаток имеет знак делимого: −7 % 2 = −1. Деление целого на ноль — паника в любом профиле.

Приведение типов

Раз неявных преобразований нет, их пишут явно. Есть два основных способа.

From — преобразование без потерь. Оно существует только там, где любое значение исходного типа помещается в целевой: u32::from(hp) для hp: u16, i64::from(x) для x: i32, f64::from(n) для n: u32. Если потеря возможна, такой функции просто нет, и код не скомпилируется.

as — приведение, которое всегда компилируется и никогда не паникует, но может молча изменить значение:

src/main.rs44 255 -56 3 0 255 0 6000000
fn main() {
    println!("{}", 300_i32 as u8);
    println!("{}", -1_i32 as u8);
    println!("{}", 200_u8 as i8);
    println!("{}", 3.9_f64 as u8);
    println!("{}", -5.0_f64 as u8);
    println!("{}", 300.0_f64 as u8);
    println!("{}", f64::NAN as i32);
    let hp: u16 = 60_000;
    let wide = u32::from(hp) * 100;
    println!("{wide}");
}
ПриведениеПравилоПример
целое → более узкое целоеотбрасываются старшие биты300 → 44
знаковое ↔ беззнаковое того же размерабиты те же, читаются по-другому (§7)−1 → 255, 200 → −56
дробное → целоедробная часть отбрасывается, выход за границы насыщается3,9 → 3, −5,0 → 0, 300,0 → 255
NaN → целоеполучается 0NaN → 0
char → u32номер символа в Юникоде'я' → 1103
char → u8номер символа, обрезанный до 8 бит'я' → 79

Правило для курса: расширяйте через From, а as для сужения используйте, только когда можете доказать, что значение помещается. Для сужения с проверкой есть TryFrom: u8::try_from(300) вернёт ошибку вместо 44. Его разберём вместе с обработкой ошибок в лекции 10.

§6Кортежи и массивы

Коротко о двух составных типах, которые понадобятся уже в следующей лекции. Оба имеют фиксированный размер, известный при компиляции.

src/main.rsАрия: уровень 7, точность 0.85 / 7 / 12 5 100
fn main() {
    let hero: (&str, u32, f64) = ("Ария", 7, 0.85);
    let (name, level, accuracy) = hero;
    println!("{name}: уровень {level}, точность {accuracy}");
    println!("{}", hero.1);

    let damage = [12, 7, 30, 4, 18];
    let zeros = [0u8; 100];
    println!("{} {} {}", damage[0], damage.len(), zeros.len());
}
  • Кортеж собирает значения разных типов. Поля читаются по номеру (hero.1) или разбираются шаблоном (let (name, level, accuracy) = hero). Пустой кортеж () называется unit и означает «нет значения»: его возвращает функция без ->.
  • Массив [T; N] хранит N значений одного типа. [0u8; 100] — сто нулей. Длина входит в тип: [i32; 5] и [i32; 6] — разные типы.
  • &str в кортеже — строковый литерал. Строки подробно разберём в лекции 5.

Индекс за пределами массива — паника во время выполнения. Если компилятор видит выход за границу заранее, как в let a = [1, 2, 3]; a[5], он остановит сборку ошибкой «this operation will panic at runtime» (линт unconditional_panic). Для изменяемых списков есть Vec, это лекция 8.

§7Переполнение

В u8 помещаются числа от 0 до 255. Что будет, если к 255 прибавить 1? Ответ зависит от того, когда переполнение обнаружено.

компиляция

Литерал не помещается в тип: let x: u8 = 256; → ошибка, линт overflowing_literals.

компиляция

Компилятор сам может вычислить результат: let x: u8 = 255; let y = x + 1; → ошибка «this arithmetic operation will overflow», линт arithmetic_overflow.

запуск, dev

Значение стало известно только при работе программы → паника «attempt to add with overflow». Включено overflow-checks.

запуск, release

Проверка выключена → результат заворачивается по модулю 2n: 255 + 1 = 0. Это определённое поведение, а не неопределённое, как переполнение знаковых в C и C++.

Чтобы увидеть поведение во время выполнения, значение надо спрятать от компилятора. Для этого есть std::hint::black_box: функция возвращает аргумент как есть, но компилятор не может заглянуть внутрь и вычислить результат заранее.

src/main.rscargo run: паника · cargo run --release: 0
use std::hint::black_box;

fn main() {
    let x: u8 = black_box(255);
    let y = x + 1;
    println!("{y}");
}
thread 'main' panicked at src/main.rs:5:13:
attempt to add with overflow

Две операции паникуют в любом профиле, независимо от overflow-checks: деление целого на ноль («attempt to divide by zero») и i32::MIN / -1 («attempt to divide with overflow»): результат 2 147 483 648 в i32 не помещается.

Дополнительный код

Знаковые целые хранятся в дополнительном коде (two's complement). Биты у u8 и i8 одни и те же, разное только их прочтение: если старший бит равен 1, число в i8 считается отрицательным, и из него вычитается 256.

Переполнение по намерению

Полагаться на поведение release нельзя: в debug тот же код паникует. Если переполнение возможно, выберите поведение явно. У каждого целого типа есть четыре семейства методов:

src/main.rs44 / None / Some(250) / 255 / (44, true)
use std::hint::black_box;

fn main() {
    let x: u8 = black_box(200);
    println!("{}", x.wrapping_add(100));
    println!("{:?}", x.checked_add(100));
    println!("{:?}", x.checked_add(50));
    println!("{}", x.saturating_add(100));
    println!("{:?}", x.overflowing_add(100));
}
СемействоРезультат200u8 + 100Где в игре
wrapping_*заворачивает по модулю 2n44счётчик тиков, хеши
checked_*Some(x) или None при переполненииNoneпокупка: хватает ли денег
saturating_*упирается в MIN или MAX255здоровье, кошелёк с лимитом
overflowing_*кортеж (завёрнутое значение, был ли перенос)(44, true)длинная арифметика

Методы есть для add, sub, mul и других операций. Option с вариантами Some и None подробно разберём в лекции 7; пока достаточно того, что {:?} его печатает, а assert_eq! умеет сравнивать.

fn main() {
    let hp: u16 = 20;
    let hp = hp.saturating_sub(35);
    let tick: u8 = 255;
    let tick = tick.wrapping_add(1);
    let gold: u32 = 50;
    let after_buy = gold.checked_sub(80);
    println!("{hp} {tick} {after_buy:?}");
}
Если вы пришли из C#

В C# по умолчанию действует unchecked: int.MaxValue + 1 молча становится int.MinValue и в Debug, и в Release, если не включить CheckForOverflowUnderflow или не написать checked. Rust в debug ловит переполнение всегда, поэтому ошибки находятся ещё при разработке.

§8println! и форматирование

Для второго задания понадобится печатать ровные таблицы. Строка формата println! проверяется при компиляции: лишний или недостающий аргумент — ошибка сборки.

src/main.rsвывод в таблице ниже
fn main() {
    let name = "Гоблин";
    let hp = 30;
    println!("{name}: {hp} HP");
    println!("[{:>6}] [{:<6}] [{:^6}]", hp, hp, hp);
    println!("[{:08b}] [{:#x}] [{:.2}]", 5u8, 255, 3.14159);
    println!("{:?} {}", (1, 2.5), u8::MAX);
    println!("{hp:>5}|");
}
